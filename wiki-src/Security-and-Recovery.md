# 下载完整性、反代与回滚安全

## 如何判断包是否可信？

组件来自上游稳定版和构建仓库的 GitHub Releases。更新器比较 **GitHub Release API 的资产 SHA256 digest → Manifest → 实际安装包 SHA256**，再检查设备身份、架构、原文件与当前预案。

**项目暂未采用独立数字签名。** 摘要能发现下载损坏与大多数文件不一致，但如果发布权限被盗、API 与文件被同一恶意代理伪造，不能提供端到端真实性证明。

## GitHub 下载代理

- **关闭**：官方 API 和文件都直连（默认）。
- **仅下载文件**：官方 API 直连，文件可经可信 HTTPS 反代（优先推荐）。
- **API + 文件**：两者都经过代理；意味着用户进一步信任代理站点。
- 已预置反代地址只是可编辑的候选，**不保证长期可用**；必要时采用自有可信 HTTPS 反代。不得关闭 TLS 证书校验。

## 更新和恢复边界

- **更新前**：核对设备与包归属、锁与预案、所需空间、完整恢复包和配置；检查软件包是否已经被手动修改。
- **更新时**：只使用校验过的固定本地包；不从软件源自动补装依赖，不替换固件分区，不主动重启 PassWall。
- **更新后**：核实实际 ELF SHA256、软件包数据库版本及配置；异常执行已验证的回滚路径并保留中断事务。
- **opkg**：使用与当前安装状态一致的本地恢复 IPK，允许恢复原有版本与手动改过的 ELF。
- **AX6S APK**：要求原始版本 APK 和文件 SHA256 可重建；恢复原版本与配置，并原样保护 `/etc/apk/world`；未知版型绝不强制安装。

服务可能仍有正在执行的旧二进制进程；包升级成功**不表示所有旧进程立即换成新版**。也不能保证包原有脚本及服务日后重载完全无影响。

## 实机操作前

准备局域网或串口恢复通路、原始固件和安装包备份，先运行只读诊断，再进行经同意的安装/回滚验收。AX6S 的剩余真机项目见 [验收待办](https://github.com/wekingchen/luci-app-component-updater/blob/main/docs/ax6s-hardware-acceptance-checklist.md)。
