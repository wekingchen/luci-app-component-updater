# 系统架构

## 一份产品界面，两类原生安装引擎

`LuCI（中文响应式 UI） → rpcd → component-updaterctl → 适配器 / 原生包管理器`。

- **LuCI**：显示当前组件、官方最新版本、兼容性、操作进度、恢复状态；把检查、下载并更新、回滚作为三个主要入口；代理设置是独立配置页。
- **rpcd/ACL**：只暴露受限动作，不依赖任意远程命令执行。
- **后端**：检查设备、安装预案、官方发行信息、摘要与存储空间；处理锁、备份、日志和中断恢复。
- **opkg**：为受支持的 IPK 环境生成本机恢复 IPK，经原生 opkg 升级与降级。
- **APK**：AX6S 专用 APKv3 引擎检查固定固件/包数据库及归属、预存原版恢复 APK，保存配置和 `/etc/apk/world`，再经原生 apk 离线安装/回滚；未知 APK 环境默认禁止安装。

## 发布架构

1. 上游 NaiveProxy 官方稳定版出现后，云端提前下载官方资产并验证 SHA256。
2. UPX 5.2.1 `--lzma --best` 压缩，校验 ELF 架构、解压往返与 ARM64 运行，按支持架构生成组件 IPK。
3. 经过独立原生 opkg 根文件系统和 ARM64 回归后，发布 IPK 组件候选。
4. AX6S APK 构建接续已验证的 IPK 二进制，使用原始固件 APK 数据重建原版恢复包，并生成新的 APKv3 升级包。
5. 云端 APK 安装、回滚及生产控制器回归通过后，才具备 APK **RC** 发布资格；硬件验收另算。

**管理器** IPK 和 APK 版本统一、同一个 Release；**组件** IPK 与 APK 分别按自身验证流程与 Release 交付。组件当前仅为 NaiveProxy；不是任意程序通用更新器。

## 本地设备不负责压缩

固件内 LuCI 查找已发布候选；没有云端构建就应显示等待或无候选，不能让路由器临时执行 UPX 或下载安装编译工具。更新步骤不得暗中下载缺失依赖。
