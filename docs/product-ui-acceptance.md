# 组件更新器 V0.3.0 界面验收

本轮为**前端重构**：不改变现有 IPK 下载、SHA-256 校验、更新、恢复或下载中转实现。V0.2.3 的原生安装/回滚实机结论不能直接视为 V0.3.0 新界面已经通过双机验收。

## 设计要求

- 全部操作说明、状态、错误反馈使用中文。NaiveProxy、GitHub、IPK、opkg、SHA-256、设备架构、版本号属于专有名词或技术标识，可保留。
- 主要操作始终保持三项：检查官方更新、下载并更新、恢复上一个版本。
- “下载并更新”只在获得仍有效的可安装候选包时允许点击；等待检查、云端准备、已是最新版、安装进行中必须禁用。
- 操作进行中所有三项按钮禁用，防止并行更新；确认安装和恢复均有二次确认。
- 使用页面内可关闭的单条操作反馈，不使用低对比度的 LuCI 原生堆叠通知。未知英文后端错误映射为通用中文说明，原始信息只保留在系统日志。
- 正常状态一屏可见，设备及软件包信息分组展示；构建版本、安装文件、校验声明隐藏在可展开详情中。
- 对轮询结果做差异判断，状态没有变化时不重复替换 DOM；展开的技术详情在有状态变化的刷新后仍保持展开。
- 两种下载设置模式：官方 API 直连+仅文件中转、查询和文件均中转。用户应在界面中看见后者的可信度风险说明。
- 不额外加载 CDN、图标库、外部字体或框架，不依赖现代 rpcd-mod-ucode。

## 自动化门禁

运行：

```sh
node tests/luci_ui_smoke.js
python3 -m unittest discover -s tests -v
python3 tools/package_ipk.py --out dist
```

CI 还会校验 LuCI JavaScript 解析、后端 Shell 语法、老/新原生 opkg 往返安装以及可安装 IPK 产物。

## 实机核验清单

1. GL-MT3600BE 的老 LuCI 与 N1 的新 LuCI 分别打开组件更新，检查页面内容及按钮可用性。
2. 在手机窄屏、桌面宽屏测试：无横向滚动、无按钮超出、版本号可换行、卡片不会遮挡标题。
3. 在待检查、最新版、待安装、云端准备、安装中、更新失败、需要恢复七类状态检查状态文案及操作可用性。
4. 点击检查更新，确认只出现**一条**清晰中文页面提示；持续停留期间自动刷新不会折叠用户打开的技术详情。
5. 打开下载设置，验证四个预设地址、自定义地址校验、中转失败直连回退和保存按钮正常。
6. 更新和恢复对话框可显示、可取消；并行点击不产生重复操作。实际更新/回滚仍沿用原有单独签署的实机验收步骤。
7. 更新完成后立即检查系统软件包版本与实际 NaiveProxy 版本，确认 PassWall 不被更新器主动重启；运行中旧进程允许暂存。

不经过第 1–7 项的设备浏览器核验，不应宣称 V0.3.0 “商业发布已全量验收”；先以 RC 候选交付。
